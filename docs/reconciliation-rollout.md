# 渠道账单、支付/退款对账上线验收

本文对应 OpenSpec `implement-channel-bill-reconciliation`。代码具备真实 SDK 接口与本地验证路径，不代表已经完成真实商户验收。自动确认默认关闭；本次未连接生产渠道、执行生产迁移或发生真实资金操作。

## 运行行为

- `reconcile.enabled`：默认 `false`；启用真实账单下载、日历恢复、支付/退款核对、本地迟到资金再检查。需要对应 `pay.alipay` / `pay.wechat` 启用、账号表身份匹配以及新增迁移。
- `reconcile.interval`：留空默认 `1m`，正 Go duration。它是每轮推进间隔，不是账单周期；账单仍按东八区日切。旧的显式 `24h` 仍会生效，但分页与补偿每24小时才推进，不适合积压恢复。需按每日明细量和数据库延迟验算处理能力。
- `reconcile.auto_confirm`：默认 `false`，`true` 必须同时 `enabled=true`。只对完整发布证据中的已有支付/退款进行独立成功查单和既有确认事务；不会新发起支付、退款或把未查到当作资金失败。

元信息响应上限64KiB、下载64MiB、展开256MiB、单行1MiB、明细100万条。账单拉取最多30秒，每工作片45秒、数据库事务5秒、租约60秒，比较每页100条。每账号每轮最多比较6400条源明细、历史回填100条、本地流水核对100条、独立补偿8条；默认每分钟一轮时，持续新增超过100笔/账号/分钟会使本地反向核对积压，必须按实际规模验收。超过上限明确失败；不是无限容量承诺。内存不随全日账单和全日财务流水同时增长。

单账号一轮总预算365秒，后面的本地核对与补偿使用剩余时间；批次处理持续接近上限时，会推迟这两步。本机测试不证明生产恢复时延，容量验收须同时量测最老未核对流水和补偿等待时间，不能只检查worker仍在运行。上述数量是每轮上界，不是吞吐保证。

微信目前支持普通商户 APIv3 的现代 `ALL` 人民币账单，不请求压缩；摘要验证原始CSV字节。退款行按受理日出现，只有后续退款查询明确成功才允许确认到账。支付宝目前支持国内 `trade` 日账单明确中文字段集合、UTF-8/GBK的单层ZIP，申请 `secure=true`；模板不匹配或下载地址未列入官方精确域名集合时失败关闭。支付宝退款不使用原支付号充当独立退款流水号。

支付宝完整性证明来自明细头尾、交易/退款笔数及同口径实收汇总；附加汇总CSV只校验编码、完整读取与CRC，不宣称逐项核对所有优惠和净结算列。原ZIP的SHA-256仅供审计，不是渠道文件签名。信用预授权、境外/非人民币及间连子商户不在本轮范围内，独立查单发现这些模式时拒绝自动确认。

同商户账单可能包含其他应用；未知归属、原支付身份冲突、币种/本金差异、退款人工终态及撤销退款保持待核实。人工 `HandleReconcileDiff` 仍只写处置与审计，不执行资金动作。`batch_id=0` 的本地待核实证据表示尚不能绑定完整账期，不会自动补偿。

自动确认要求冻结商户、应用和账号版本可证明一致。变更账号凭据或商户归属必须递增 `config_version`；缺失历史快照、版本不符和异常支付来源退款转人工核实。支付查单返回后还会在订单→尝试锁内二次校验，若其他支付已先完成订单，本次补偿不插入另一笔异常资金流水。普通合法回调的异常资金记录语义仍保留。

## 数据库与发布顺序

1. 在非生产副本验证新增SQL草稿、索引执行计划、备份恢复以及DDL锁窗口。前两份20261012迁移与本轮000003按顺序执行；不得拿 `schema.sql` 重建生产库。
2. 暂停对账与自动确认，完成增量迁移。旧批次/差异保留算法修订号1，新支付+退款算法为内部修订号2；这不是项目主版本升级。
3. 全部写入实例升级并排空旧事务后启动历史回填。新流水与本地核对唤醒同一事务提交，避免小ID迟提交或旧日期回调永久遗漏。
4. 先开启 `enabled=true, auto_confirm=false`。确认账单源、日期、商户/应用范围、方向本金汇总、差异数量和历史回填进度。
5. 完成下表外部验收并明确处置责任后，按商户部署分组灰度自动确认。关注不可解异常、失败批次、最老未核实记录、下载失败与临时目录容量。
6. 回滚先停自动确认和对账，再回滚应用；保留新表、字段、已封存证据、资金流水和审计。不能自动删除流水或通过反向修改金额“撤销”已确认资金。

已完成的本地命令、覆盖场景及未完成项记录在本轮 OpenSpec `verification.md`，只有真实输出才能标记通过。本地测试不能保证所有生产情况“万无一失”。

差异行是持久事实；告警在事务提交后经既有告警组件发送，并不具备与资金Outbox相同的可靠投递保证。提交后进程退出或告警通道失败可能漏掉通知，生产须持续扫描未解决差异和积压，不能用“没有收到告警”判断已经对平。
