# 微信 APIv3 账单源

`New(ctx, Config)` 离线加载现有商户凭据；运行时通过 `bill.Source` 与 `bill.Verifier` 使用。公钥模式要求公钥 ID 和公钥来源齐全，未配置该模式时使用静态平台证书。PEM 优先于对应路径。没有自动下载证书或后台刷新任务，证书/公钥轮换由现有部署配置管理。

- `Fetch` 签名申请 `bill_type=ALL`，不传 `tar_type`，申请响应经过官方 SDK RSA 验签。下载请求仍使用同一商户签名，下载响应依协议没有签名，必须与已验签元信息中的 SHA1 匹配。哈希核对发生在去 BOM、换行处理和字段解析之前。完整解析成功后，Summary 返回 `DigestAlgorithm=SHA1` 与规范化小写十六进制摘要供批次审计保存。`NO_STATEMENT_EXIST` 仅返回显式缺账标记，应用层不得发布为空账单或自动对平。
- 只支持 UTF-8 现代 ALL 中文模板（完整 27 个已知字段与 7 个汇总字段），允许字段重排和额外说明列；缺失、重复头、旧格式、压缩文件、金额/行数合计冲突均失败。自定义文本按官方转义保留，文件不是 RFC4180 引号 CSV。
- 普通商户号必须一致、特约商户号必须为 `0`；真实 AppID 保留，不按构造配置填造或预先过滤。支付本金取订单金额，退款本金取申请退款金额；结算金额和手续费仅用于全文件汇总核对。
- 账期固定东八区，支持前三个月且必须早于当天。退款 `EventAt` 是受理时间；`Status` 保留为 `REFUND:SUCCESS/PROCESSING/FAIL/CHANGE` 或 `REVOKED:<状态>`，不是当下资金结论。
- `emit` 同步写入暂存，资金身份唯一性由暂存层约束。解析尾汇总前可能已经 emit；调用方只有在 `Fetch` 成功后才能发布整个导入。下载、行长、条数限额复用 `billio`，解析器仅保留当前行和固定大小合计。
- `Verify` 使用完整官方查询响应：支付校验商户/AppID/两个支付身份/总本金/币种；退款先查原支付归属，再核四个交易与退款身份、原订单总额、退款本金和币种。仅渠道明确成功返回确认；原支付处于 `REFUND` 仍是已付款事实。`REVOKED` 留人工，负面结果没有本地副作用。成功时间缺失保持零值，不能拿退款受理时间或本机时间填充。

生产 HTTP 使用公共 `billio` 的精确 HTTPS 主机、DNS/实际拨号公网校验、禁代理/重定向、超时和 Body 限额。只允许官方当前示例中的两条下载路径；未知实际下载域名/路径拒绝，并需商户验收后才能扩展。SDK 会在验签后替换响应 Body，本包在读到 EOF/错误时关闭原始 Body，并清理所有临时文件。

测试使用本地临时生成的 RSA 密钥、X509 证书、签名响应与假的 HTTP transport；不会请求真实渠道，也不使用商户凭据。覆盖摘要/身份/金额/状态/时间反例、并发复用、资源清理、100,000 行生成式解析和超过 64 MiB 下载。真实商户模板、优惠券实例及实际域名仍是上线验收项。

官方契约：[申请账单](https://pay.wechatpay.cn/doc/v3/merchant/4013071227)、[下载账单](https://pay.wechatpay.cn/doc/v3/merchant/4013071238)、[字段说明](https://pay.wechatpay.cn/doc/v3/merchant/4013071246)。SDK 版本沿用 `go.mod` 的 `github.com/wechatpay-apiv3/wechatpay-go v0.2.21`。
